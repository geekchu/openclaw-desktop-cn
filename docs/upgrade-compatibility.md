# Windows 安装程序升级兼容性方案

## 概述

本文档描述了 OpenClaw Desktop 从旧版本（`OpenClaw桌面版`）升级到新版本（`OpenClaw Desktop`）的完整兼容性处理方案。

## 版本信息

- **旧版本名称**: `OpenClaw桌面版`（中文名）
- **旧版本安装目录**: `%LOCALAPPDATA%\OpenClaw桌面版`
- **新版本名称**: `OpenClaw Desktop`（英文名）
- **新版本安装目录**: `%LOCALAPPDATA%\OpenClaw Desktop`
- **用户数据目录**: `%USERPROFILE%\.openclawcn\`（保留不变）

## 升级兼容性问题

### 发现的问题

1. **开始菜单快捷方式残留** ⚠️
   - 旧版本快捷方式指向已删除的目录
   - 用户点击会报错"找不到文件"

2. **注册表卸载信息残留** ⚠️
   - "添加或删除程序"中会有两个条目
   - 旧版本条目指向已删除的目录

3. **自动启动项残留** ⚠️
   - 开机自启动注册表项残留
   - 开机时会尝试启动不存在的程序

4. **端口冲突问题** 🔴
   - 两个版本同时存在时都尝试占用 28789 端口
   - 可能导致新版本无法启动

5. **配置文件兼容性** ⚠️
   - 配置文件格式可能变化
   - 需要版本检查和迁移

## 解决方案

### 1. 安装程序层面（NSIS）

#### 文件位置
`src-tauri/installer_hooks.nsi`

#### 实现逻辑

```nsis
!macro CleanupOldVersion
  ; 检测旧版本目录
  StrCpy $1 "$LOCALAPPDATA\OpenClaw桌面版"
  
  ${If} ${FileExists} "$1\*.*"
    ; 1. 优先调用旧版本的卸载程序
    StrCpy $2 "$1\uninstall.exe"
    ${If} ${FileExists} "$2"
      ; 调用卸载程序并等待完成
      ExecWait '"$2" /S' $0
      Sleep 2000
      
      ; 检查卸载是否成功
      ${If} ${FileExists} "$1\*.*"
        ; 卸载失败，执行手动清理
      ${Else}
        ; 卸载成功
        Goto cleanup_done
      ${EndIf}
    ${EndIf}
    
    ; 2. 手动清理（如果卸载程序不存在或失败）
    ; 2.1 停止旧版本进程
    ; 2.2 删除开始菜单快捷方式
    ; 2.3 删除桌面快捷方式
    ; 2.4 删除自动启动项
    ; 2.5 删除注册表卸载信息
    ; 2.6 删除其他注册表项
    ; 2.7 删除安装目录
    
    cleanup_done:
  ${EndIf}
!macroend
```

#### 关键改进

1. **优先调用卸载程序**
   - 使用 `ExecWait '"$2" /S' $0` 等待卸载完成
   - 不使用 `_?=$1` 参数，让卸载程序正常删除目录
   - 记录退出码，方便调试

2. **完整的手动清理**
   - 删除所有快捷方式（开始菜单、桌面、启动文件夹）
   - 删除所有注册表项（卸载信息、自动启动、应用配置）
   - 删除安装目录

3. **强制清理，不询问用户**
   - 避免用户选择"跳过"导致端口冲突
   - 自动执行清理流程

### 2. 应用层面（Rust）

#### 文件位置
- `src-tauri/src/migration.rs` - 配置迁移模块
- `src-tauri/src/main.rs` - 集成迁移检查

#### 实现逻辑

```rust
// 应用启动时自动执行配置迁移检查
match migration::check_and_migrate() {
    MigrationResult::NoMigrationNeeded => {
        // 配置版本已是最新
    }
    MigrationResult::Success { from_version, to_version, backup_path } => {
        // 迁移成功，记录日志
    }
    MigrationResult::Failed { error } => {
        // 迁移失败，记录错误（不阻止应用启动）
    }
}
```

#### 功能特性

1. **版本管理**
   - 在配置文件的 `meta.version` 字段中存储版本号
   - 当前版本：`0.2.9`

2. **自动迁移**
   - 从无版本号的旧版本（legacy）迁移
   - 从 0.1.x 版本迁移
   - 从 0.2.x 早期版本迁移

3. **配置备份**
   - 迁移前自动备份到 `~/.openclawcn/backups/openclaw.json.backup-YYYYMMDD-HHMMSS`
   - 自动清理旧备份（保留最近10个）

4. **配置完整性检查**
   - 确保必要的顶级字段存在
   - 确保关键配置结构完整

### 3. 数据层面

#### 用户数据保护

- **保留目录**: `%USERPROFILE%\.openclawcn\`
- **保留内容**:
  - `openclaw.json` - 主配置文件（会迁移）
  - `exec-approvals.json` - 执行审批配置
  - `env` - 环境变量文件
  - `sessions/` - 会话数据
  - `credentials/` - 凭证数据
  - `backups/` - 配置备份

#### 备份机制

- **自动备份**: 迁移前自动备份配置文件
- **备份位置**: `~/.openclawcn/backups/`
- **备份命名**: `openclaw.json.backup-YYYYMMDD-HHMMSS`
- **自动清理**: 保留最近10个备份

## 升级流程

```
用户运行新版本安装程序
  ↓
[NSIS 安装程序]
  ↓
检测旧版本目录 ($LOCALAPPDATA\OpenClaw桌面版)
  ↓
目录存在？
  ├─ 否 → 继续安装
  └─ 是 → 清理旧版本
      ↓
      检查卸载程序 (uninstall.exe)
      ↓
      卸载程序存在？
      ├─ 是 → 调用卸载程序 (/S 静默模式)
      │       ↓
      │       等待卸载完成
      │       ↓
      │       检查目录是否被删除
      │       ├─ 是 → 显示成功消息 → 继续安装
      │       └─ 否 → 执行手动清理 → 继续安装
      │
      └─ 否 → 执行手动清理 → 继续安装
  ↓
安装新版本
  ↓
[应用启动]
  ↓
检查配置文件版本 (meta.version)
  ↓
版本匹配？
  ├─ 是 → 正常启动
  └─ 否 → 执行配置迁移
      ↓
      备份旧配置
      ↓
      执行版本特定的迁移函数
      ↓
      更新版本号
      ↓
      保存新配置
      ↓
      正常启动
```

## 测试指南

### 测试场景1：全新安装

**步骤**:
1. 确保没有旧版本安装
2. 运行新版本安装程序
3. 启动应用

**预期结果**:
- 安装成功
- 创建新配置文件，版本号为 `0.2.9`
- 应用正常启动

### 测试场景2：从旧版本升级（有卸载程序）

**步骤**:
1. 安装旧版本 (`OpenClaw桌面版`)
2. 确认 `%LOCALAPPDATA%\OpenClaw桌面版\uninstall.exe` 存在
3. 运行新版本安装程序
4. 启动应用

**预期结果**:
- 自动调用旧版本卸载程序
- 旧版本目录被完全删除
- 显示"Old version (OpenClaw桌面版) has been uninstalled"消息
- 用户数据 `~\.openclawcn\` 保留
- 配置文件自动迁移
- 应用正常启动

### 测试场景3：从旧版本升级（无卸载程序）

**步骤**:
1. 手动创建旧版本目录结构（无 `uninstall.exe`）
2. 运行新版本安装程序
3. 启动应用

**预期结果**:
- 检测到卸载程序不存在
- 执行手动清理流程
- 删除目录、快捷方式、注册表项
- 应用正常启动

### 测试场景4：配置文件迁移

**步骤**:
1. 准备旧版本配置（无 `meta.version`）
   ```bash
   echo '{"gateway":{},"agents":{}}' > ~/.openclawcn/openclaw.json
   ```
2. 启动应用

**预期结果**:
- 自动检测配置版本不匹配
- 创建备份文件
- 执行配置迁移
- 版本号更新为 `0.2.9`
- 应用正常启动

### 测试场景5：卸载程序执行失败

**步骤**:
1. 安装旧版本
2. 锁定某些文件（模拟文件占用）
3. 运行新版本安装程序

**预期结果**:
- 卸载程序执行但目录未完全删除
- 自动切换到手动清理流程
- 显示警告消息
- 安装继续进行

## 故障排查

### 问题1：旧版本目录未被删除

**可能原因**:
- 旧版本进程仍在运行
- 文件被其他程序占用
- 权限不足

**解决方法**:
1. 手动停止旧版本进程
2. 重启计算机
3. 手动删除旧版本目录

### 问题2：配置迁移失败

**可能原因**:
- 配置文件损坏
- 权限不足
- 磁盘空间不足

**解决方法**:
1. 检查日志文件
2. 从备份恢复配置
3. 删除配置文件，重新初始化

### 问题3：端口冲突

**可能原因**:
- 旧版本未被完全清理
- 其他程序占用 28789 端口

**解决方法**:
1. 检查端口占用：`netstat -ano | findstr :28789`
2. 停止占用端口的进程
3. 手动删除旧版本目录
